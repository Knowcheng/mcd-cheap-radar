# 验证记录

时间：2026-10-14，北京时间。验证由本人提供的本机凭证触发，未公开个人凭证、位置或券兑换码。

## 官方联网验证

- `initialize` / `notifications/initialized` / `tools/list` 成功，实际发现 35 个工具。
- 真实调用附近门店、菜单、门店券、可领券、活动日历、价格计算。
- 两家门店 16 次候选计价通过，过滤独立酱料，已验证最低现金实付为 500 分的圆筒冰淇淋/灰焰圆筒，随后有 700 分苹果片、750 分饮用水等。
- 本机 HTTP 网页 API：连接 200、真实扫描 200，24 个有效报价，最低 500 分。返回中不含 Token，测试后删除会话。
- 修复分类查询后，主食模式查询 3 家门店、112 个主食候选，其中 24 次官方计价均有效，包含 2000 分套餐和 2290 分三件套。价格仅代表当次查询。
- 上述验证没有领券、下单、买卡、积分扣减或抽奖。领券功能的传输和确认保护使用本地 HTTP 测试。

价格是当次门店/账号/时段的结果，后续必须重新验证。真实原始数据只保存在 Git 忽略目录；本报告没有用户地址、坐标、门店关联个人位置或实际 couponCode/couponId。

## 自动测试

`npm test` 使用 Node 内置测试器。覆盖排序、券商品码、异常报价、过期券、候选截断、数据格式、城市业务校验、食品筛选、JSON/SSE/session 传输、账号隔离、同源保护、确认领券、会话销毁、公网拒收 Token 和手动变化判断。

分类回归：即使菜单前面有 30 个更便宜的小食和饮品券，主食查询仍会把报价预算用于主食；网页 API 传递并校验分类。共 28 项测试通过。

`npm run check` 检查源码语法、必需文档、参赛声明 Git blob SHA、占位配置、真实 Token 不进入已跟踪文件，以及禁止的订单/积分工具不被代码调用。
