# 麦麦低价雷达 · mcd-cheap-radar

**便宜，是今天吃它的理由。**

不知道吃什么？不用先挑餐品。看看附近当前有哪些低实付餐品、哪些券能用、应该去哪家门店，再决定今天吃什么。

项目基于麦当劳中国官方 MCP，面向中国大陆地区个人使用，提供手机友好网页、CLI 和 Agent Skill。代码原创，零运行依赖。

> 独立开发的参赛作品，非麦当劳官方产品。网页初始展示**自造演示数据**，不代表实际价格或可领优惠。真实功能只能在本人设备主动使用。公网生产模式拒收个人 Token；后续公众号实时服务须先获得官方授权。

## 解决什么问题

- **给一个吃的理由**：不要求用户先想吃什么，咖啡、小食、汉堡、套餐都能参与最低实付排序。
- **发现券、知道怎么用**：查可领券与门店可用券；每个推荐说明券名、门店、点餐步骤。领券后重新查询验证。
- **比较附近门店**：同一账号、同一到店方式，在指定距离内逐门店查询菜单和券，按官方实付排序；平价优先近店。
- **价格可信**：菜单标价只是候选优先级提示。推荐金额必须来自 `calculate-price`，整数分计算；异常 0 元、缺失价格、错误商品不进入结果。
- **变化由你主动查看**：手动检查新券和更低价格。没有后台轮询、自动抢券或限量秒杀承诺。
- **免费也要核验**：0 元推荐必须有明确免费券且官方返回对应商品；不把卡、餐具、酱包等当成“最低价餐品”。

当前优先支持**到店取餐**。外送配送上下文、会员卡购买、积分兑换、自动下单不包含在本版本。

## 快速体验

需要 **Node.js >=22.9.0**，无需 `npm install`。

```bash
git clone https://github.com/Knowcheng/mcd-cheap-radar.git
cd mcd-cheap-radar
npm start
```

打开 <http://127.0.0.1:3417>，可直接体验演示。支持饮品/小食/主食筛选、0 元及预算筛选、点餐步骤、复制分享。所有演示价格有明显标识。

命令行演示：

```bash
npm run demo
```

## 本人真实使用

1. 在 [麦当劳开放平台](https://open.mcd.cn/mcp)申请个人 MCP Token，并阅读[官方服务规则](https://cdn.mcd.cn/cms/pages/MCPServerRules.html)。
2. 在本人本机启动网页，点击“连接我的账号”，输入自己的 Token。
3. 填写城市和附近商场/地铁站/街道，选择距离，点击“发现低价”。
4. 看最低实付餐品以及用券步骤。需要领券时点击“一键领免费券”，**当次确认**后执行官方领取，再重新计价。

Token 不写入浏览器存储或文件，不作为 URL 参数；个人本机服务内存会话在 **30 分钟**后销毁，点击“断开”立即销毁。服务器环境变量中的 Token 不会作为网页默认账号。

开发探测和本机主动查询可以配置本地 `.env`（已被 Git 忽略）：

```bash
cp .env.example .env
# 在本人设备编辑 .env，填入个人 Token、城市和附近地点。
npm run probe
npm run scan -- --stores 2 --quotes 16 --radius 5000
npm run scan -- --category meal
# 仅在本人明确决定领取时：
node --env-file=.env src/cli.mjs claim --confirm
```

不要将这些命令加入 cron、无人值守脚本或批量账号任务。官方规则限制脚本/自动化调用；工具示例与开发验证不构成对这些使用方式的许可。若对个人客户端的具体使用边界有疑问，以麦当劳官方确认结果为准。

## Agent Skill

把本仓库的 [SKILL.md](SKILL.md)加入支持 Skill 的客户端，并使用 [mcp-config.example.json](mcp-config.example.json)接入官方 MCP。配置方式以客户端的环境变量处理能力为准，不能将真实凭证提交到仓库。

示例：

> 我在佛山市，附近是某某商场。3 公里内，咖啡、小食、汉堡都行。帮我找本次查询里实付最低的餐品，说明用哪张券、去哪家店、怎么点。先只查，不领券也不下单。

Skill 支持在已连接官方 MCP 的个人 AI 客户端中直接按用户指令编排工具；无需把 Token 发给本项目运营者。

## 搜索范围与价格说明

默认最多查 3 家门店、验证 24 个候选；CLI 可调整，最大 5 家/100 个候选。券专用商品候选优先，再按菜单提示价排序，并轮流在不同门店计价，避免首家门店耗尽查询预算。

选择“主食套餐”“饮品”或“小食甜品”时，会先从门店菜单和可用券中筛选该分类，再使用报价预算。实时查询后点击分类会发起一次该分类的新查询；修改地点或距离后需点击“发现低价”。CLI 的 `--category` 支持 `all`、`meal`、`drink`、`snack`，默认 `all`。实付上限只筛选已经验证的报价，超出上限时页面会显示本次最低价格。

页面始终展示门店数量、已验证候选数量和覆盖限制。结果是**当前账号、所查门店、到店方式、所验证候选里的最低实付**，不承诺全渠道或全部菜单的全局最低。未领取券只是线索；领取并获取门店可用商品码后，才能验证券后价。活动文案不当作价格，也不推算未到来的优惠。

距离是官方门店接口给出的距离，不是高德步行路线。超过距离范围或距离未知的门店不参与推荐。积分或付费卡不会被当作免费。

## 已完成的真实验证

2026-10-14 使用个人凭证完成官方连接、35 个工具发现、门店/菜单/门店券/可领券/活动查询及官方计价；两店 16 次候选验证，以及本机网页 API 的连接和 24 次计价。该次已验证最低实付餐品为 **5 元圆筒冰淇淋**。这是当次门店结果，不是长期价格承诺。

详见 [MCP_INTEGRATION.md](MCP_INTEGRATION.md)和[验证记录](docs/verification.md)。未创建订单、未购买卡、未消耗积分；真实领券写操作未在开发联调中执行。

## 公众号与公开部署

可作为公众号里的开源福利介绍，并提供**免登录演示**帮助粉丝了解流程。真实优惠先由粉丝在本人设备/支持 MCP 的个人客户端使用。

官方服务规则对个人非商业使用、凭证托管和自动化调用有明确限制，因此本版**公网生产部署仅提供演示，并在后端拒收个人 Token**。面向粉丝托管实时账号服务需要官方授权、清晰的授权接入与隐私方案，不能通过共享运营者 Token 或收集粉丝 Token 实现。[部署说明](docs/deployment.md)

